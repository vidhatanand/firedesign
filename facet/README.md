## How Facet should consume it

1. **Opt in with the contract field.** A Facet system that follows Fire stores `{ "contract": "fire/1", "record": <theme record> }` (as `theme.json`), not the generated tokens. Facet calls `expandTheme(record)` from `fire/js/theme.js` (pure ES module, runs in Node and the browser) for tokens, and `themeToCss(record)` for a stylesheet a strict CSP allows. `content.json` is what Facet shows and validates for the default record; for any other record Facet regenerates it the same way (palette, type set and dials change, the scales do not).
2. **Pin the release.** Fire 0.6.0, git tag `v0.6.0` (`github:vidhatanand/firedesign#v0.6.0`). The extras bundle hash is `c3433a05984a8a3230464495ad6ac16c4d080fdb3898f354b8f8b72b9e91c5df` (SHA-256 of the lines "sha256  path" of `extras.json` files, in order). A Facet system records the tag and the bundle hash, and verifies each file's hash before an export is offered.
3. **Carry the extras.** Copy every `extras.json` file to the same relative path in the canvas or the export. Fonts marked `required: false` belong to the other type sets (`data-type`); a system on Geist needs only the required ones, and may drop the rest and the matching @font-face rules.
4. **Use the aliases.** `aliases` maps each custom property Facet generates (`--color-primary`, `--space-4`, `--shadow-md`, ...) to the Fire token with the same value, so a Facet-generated sheet can be written as `--color-primary: var(--fd-accent)` and follow the theme. Fire's tokens stay the source: Facet's `component` references should name Facet tokens only where an alias exists.
5. **Components.** Each component is `<cc-component name="Button" variant="primary">`; its props are the data attributes of the Fire markup (`variant` is `data-variant`, `iconOnly` is `data-icon-only`) and the exporter writes the Fire class (`root` in the catalogue) plus those attributes. A `children` part marks a component that takes content. Facet runs `scripts/lint-markup.mjs` on the export and `scripts/render-equal.mjs` against the board.

## Where Fire's model did not fit Facet's

- **Accent role.** Facet requires an `accent` colour; Fire has one accent. `accent` repeats `primary` and Facet may set another.
- **Status labels.** Facet has no label role for a status fill (Fire's on-danger, on-info, on-success, on-warning), so the contrast of Fire's labels on status fills is not in `pairings`. The fills are the roles; the labels stay in `fire-contract.json`.
- **Alpha colours.** Roles must be opaque: `muted` is `--fd-text-3` laid over `--fd-bg` in each mode (the contract does the same). `palette` and `state` keep the alpha as 8-digit hex (accent washes, fills, status backgrounds, lines), rounded to 1/255; state colours that Facet shows as a role (`hover.surface`, `selected.surface`, `disabled.surface`) are laid over `--fd-surface`.
- **Dark mode.** Facet's `org.codecrystal.dark` extension carries dark colours. Shadows have no dark value: `shadow` holds the light layers; Fire's dark shadows are stronger (Facet should take them from the theme record).
- **Shadow layers.** Facet allows 4 layers per shadow; `--fd-shadow-accent` has 5. Folded: --fd-shadow-accent (5 layers to 4): the last two outer layers (blur 1px and 0.5px, the same colour) became one layer with the smaller one's offset and blur and the alpha of both together, 1 - (1 - 0.14)(1 - 0.2) = 0.312. Fire's focus ring is a two-layer shadow; Facet's `focusRing` holds its 2px width and 2px offset.
- **Sizes.** Facet allows 12 `size` tokens, Fire has 29 pixel sizes. Kept: `touch` (40px, the default control on a coarse pointer; below the 44px Facet recommends, so its accessibility report shows an advisory) and the 11 most referenced by var() in Fire's CSS: control-sm (48), control-md (40), control-xs (21), control-lg (16), topbar-h (15), control-px (12), row-px (11), gutter (7), control-xl (6), size-sm (5), row (4). Left out: size-md, panel-w, rail-w, sidebar-w, size-lg, size-xs, content-max, size-2xl, size-2xs, size-3xl, size-3xs, size-4xl, size-4xs, size-5xl, size-6xl, size-xl, subnav-w, size-phone. Icon sizes are in `iconSize`.
- **Type scale.** Facet allows 16 steps; Fire has 16 sizes. Left out: --fd-text-compose (15px, the composer input), --fd-text-4xs (9px). `3xs` borrows `--fd-lh-2xs` (Fire sets no line height for it). Line heights are the ratio of Fire's line height to its size. Body is `md` (14px, 1.43), so Facet's accessibility report shows advisories for body size and line height; Fire sets text 14px on purpose.
- **Letter spacing and rem.** Facet dimensions allow three decimals; sizes such as 0.8125rem become 13px.
- **Breakpoints.** Facet's breakpoints are min-width and mobile first; Fire writes `max-width: 640px` for the phone layout and `min-width: 900px` for the wide one. `tablet` is 641px (where the wide layout starts) and `desktop` is 900px. `responsive` overrides are not written: Fire's phone overrides (smaller display and h1, 16px gutter) are max-width rules that a mobile-first override cannot say without inverting the base values.
- **Durations.** `duration` holds the five interaction durations and the stagger. The looping durations (spin 0.7s, shimmer 1.6s, pulse 1.8s, blink 1.1s, dots 1.2s) are left out: they are ambient loops, not transitions, and would make Facet report durations above 500ms. Reduced motion is `remove`: Fire sets `--fd-motion` to 0 and every duration is the token times that.
- **Dials and density.** Corners, density, line weight, text size, contrast, motion and texture are theme-record dials, not tokens Facet can model; they travel in `theme.json`.
- **Component states.** Facet takes any lower-case state name, and a web app must cover empty, loading, error and disabled. Card states map to a short vocabulary (empty, loading, error, success, disabled, hover, focus, pressed, selected, open); names that no pattern takes are dropped (101 of them, mostly transient or per-component states such as closing, dragover, masked or sending; for example accordion:closing, app:collapsed rail, app:contained, badge:removable, bars:entering, callout:dismissed, callout:remembered, card:flush). States are also read from the CSS selectors that carry the component's class (:hover, :focus, [disabled], [aria-invalid], [aria-busy], [aria-pressed], :checked, [open]); that is a heuristic, not a card.
- **Props.** Fire attributes with values are `enum` props; attributes with no value are `boolean`. `data-state`, `data-fill` and `data-fd-instant` are not props (state is set by the page; the others are layout toggles). Enums with more than 32 values would be strings; none are. `children` is Facet's own name, so no prop is called that; a `children` part says the component takes content. Components that take none are listed in the build script (`VOID`).
- **Examples.** Each `api.example` is a `<cc-component>` tag with the first value of the first two enums, not Fire markup: the docs sections that show the real markup are named in the card (`example`) and in `paths`.
- **Size.** A Facet content document may not exceed 128 KiB, and 100 full cards do not fit. The build takes the richest of 7 levels whose document fits in 126 KiB: this one is level 4 (104.7 KiB compact). At this level an entry keeps a purpose of up to 120 characters, no usage line, up to 1 do and 1 don't lines of up to 100 characters, up to 3 parts (descriptions up to 30), up to 32 props, up to 16 variants, no prop descriptions and 1 path. Longer text is cut at a word and ends with an ellipsis; the complete cards are in `contract/catalog.json`, which is carried in the extras. Level 0 is the richest; the level moves when cards are written.
