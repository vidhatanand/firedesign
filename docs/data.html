Dense, calm and exact. Hairlines instead of boxes, mono for what is technical, right-aligned figures that line up, and states for everything that can go wrong.

Cell types

Most tables are a mix of a few cell shapes: a two-line name with a leading tile, a mono identifier, a badge, an inline meter, muted metadata and an actions cell. Compose them; do not invent new ones.

Filters

A filter is a soft chip that opens a menu. At its default it reads like a button; with a value chosen it turns white, the value goes to full ink and a small × clears it. A filter bar lays out search, chips and actions and wraps instead of shrinking.

Filter chips

Filter bar

Filter bar in a 360px panel

Applied filters

  • The chip is a wrapper (fd-filter) around a trigger button and, when a value is set, a clear button. Put aria-haspopup and aria-expanded on the trigger so a menu or popover can anchor to it.
  • data-default holds the label shown when cleared. Clearing emits fd:change with value: null; call setFilter(chip, value) from your menu’s fd:select handler.
  • Applied tokens are for filters that are not visible as chips (several values, or set from a link). Removing the last one hides the row.

Pipeline

One run of staged work: a crawl, a deploy, a data job, an agent’s plan. Stages read left to right, jobs stacked in a stage run in parallel, and every job shows its status with an icon and a word for screen readers.

  1. Discover

  2. Fetch

  3. Extract

  4. Deliver

  5. On failure

  • Use it when the order and the parallelism are the point: what runs after what, and what runs at the same time. A list of steps that run one after another is fd-run-steps or fd-timeline.
  • It is not a node editor. Stages are a fixed sequence and every job of a stage feeds the next stage; there are no arbitrary edges, no dragging and no zoom.
  • Status is data-tone on the job (success, danger, warning, info, violet, neutral) with a different icon for each, data-live for work in progress (the icon turns; it stops under reduced motion) and data-state="skipped" for work that did not run. Put the status word in an fd-sr-only span inside the job: colour is never the only signal.
  • A failed job also tints its edge. Everything else keeps the surface and its hairline, so a long run of passed jobs stays quiet.
  • Connectors are drawn in CSS from each job’s first line: a stub out of every job, a rail joining the stubs of a stage, and one link to the next stage. A name that wraps to two lines grows its job downwards and the lines stay put.

Loading

While a run loads, aria-busy="true" turns every icon, name, duration and label into a placeholder, in the shape the run will have.

  1. Discover

  2. Fetch

  3. Extract

  4. Deliver

  • Render the stages you expect, with empty jobs, or the real jobs before their statuses arrive: both shimmer the same way.
  • The connectors do not flicker because nothing they hang on moves: a placeholder job is exactly one line tall, the lines are fixed to that first line, and they never animate. Only the shimmer moves, and the lines are drawn a step fainter until the pipeline is no longer busy.
  • While busy, jobs ignore clicks. Remove aria-busy and swap the contents in place.

Rules

Do

Right-align every number and give it tabular figures. Keep the actions cell last and the first column the row’s name.

Don't

Zebra-stripe rows, put cards inside table cells, or colour a whole row by status. The status cell carries the status.

Do

Say what will appear in an empty state and offer the next step: “Requests to the Ember API appear here”.

Don't

Use a meter for something with no limit, or a progress bar for something that is not moving.
