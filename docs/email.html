Components

Email

Transactional mail in the product’s own look: sign-in links, invitations, receipts and alerts. One function turns a theme record and a list of blocks into an HTML part and a plain-text part that any mail client can show.

Render an email

A module with no dependencies and no DOM, so it runs in the server that sends the mail and in the browser that previews it. Colours come from the same theme record the app loads, so a button in the email is the colour of the button in the product.

FieldWhat it does
themeA theme record. Left out, Fire’s default look. An invalid record throws.
brand{ name, logo? } (logoUrl is the older name, the name the theme record's brand uses). The logo is an https URL and the only remote image the email loads. Without one, a square in the accent colour carries the name’s first letter.
preheaderThe line a mailbox shows after the subject. It is hidden inside the message.
blocksThe content, in order. An unknown type, a missing field or an unsafe URL throws, naming the block.
localeA BCP 47 tag, default en. Sets lang and, for Arabic, Hebrew, Persian and Urdu, dir="rtl". Every word in the email is yours; nothing is translated here.

Blocks

Eight blocks cover the messages a product sends. URLs are https, http, mailto or tel; everything else is rejected, and every value is escaped.

BlockFieldsUse it for
headingtext, level 1 or 2The title. The first heading is the h1, later ones h2.
texttext (a string, or an array of strings and { text, href }), tone: "muted"A paragraph. A link carries words that say where it goes.
buttonlabel, href, fallbackThe one action. The address is printed under it for clients that block buttons; fallback: false removes that line.
codevalue, labelA one-time code to type somewhere else.
keyValuerows: [{ label, value, mono }]Facts about the event: device, place, time, amount, invoice number.
dividerA rule between parts of one message.
notetext, titleAn aside: “Not you? Ignore this email.”
footerlines, linksBelow the card: the sender’s address, privacy and help links.

The plain-text part

Send it with the HTML as a multipart/alternative message. It carries every block in reading order: buttons become a label and the address, a code is its label and value, key-value rows are one per line, and the footer follows a -- signature line.

Why the markup looks different from the rest of Fire

Mail clients drop stylesheets, ignore custom properties and strip classes, so this is the one place in Fire where styles are written inline. Everything else in Fire still uses no style attributes.

  • Layout is presentation tables in a 560px column, each marked role="presentation". Outlook gets a conditional table that holds the width.
  • Colours are opaque #rrggbb, resolved from the record. Muted text is Fire’s --fd-text-3 step composited on the ground it sits on, so it keeps 4.5:1 in light and dark; the tests check every preset, its high-contrast form and generated palettes.
  • Dark mode is a single prefers-color-scheme block plus the color-scheme meta. A client that ignores it shows the light version, which every client can read.
  • The button is a VML rounded rectangle for Outlook and a padded table cell everywhere else, so it keeps its colour and shape in both.
  • Fonts are system stacks; the editorial and book type sets use a serif stack for headings. No web fonts load.
  • Nothing loads except the logo: no script, stylesheet, tracking pixel or background image.
  • Subject lines, translations and sending belong to the product. Pass the words in, and set locale to match.
