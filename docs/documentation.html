Documentation

The docs site in the app’s own language. A two-row top bar, a neutral nav, a reading column with an “On this page” rail, and reference pages with live request and response panels, so reading the docs feels like using the product.

The docs shell

Use it for every guide and reference page. The page provides only its article; templates/docs-shell.js mounts the top bar, the section’s nav, the contents column, the article footer and the search palette. Scroll inside the box: the contents marker follows the heading you are reading.

Webhooks

Webhooks

Receive crawl, batch and monitor events at your own endpoint, as they happen.

Instead of polling a job, give Ember a URL. It sends a signed POST for each event and retries with backoff for 24 hours if your endpoint is down.

Receive events

Add a webhook object to any crawl, batch scrape or monitor. Each request carries one event with a type, a data payload and a delivery id.

Event types

  • crawl.started, crawl.page, crawl.completed and crawl.failed
  • batch_scrape.completed
  • monitor.changed, with a unified diff

Delivery

Respond with any 2xx within 10 seconds. Anything else counts as a failure and is retried after 30 seconds, then 2, 10 and 60 minutes, then hourly.

Verify signatures

Every request has an Ember-Signature header: an HMAC of the raw body with your signing secret. Compute it yourself and compare in constant time before you trust the payload.

Rotate secrets

Create a second secret, deploy it, then delete the first. Both are valid while both exist, so no event is rejected during the switch.

Test locally

Run ember webhooks listen --forward http://localhost:3000/api/ember to tunnel events to your machine while you build.

Limits

One webhook URL per job, payloads up to 10 MB, and at most 50 concurrent deliveries per team. Larger pages are sent as a signed download URL instead of inline Markdown.

Core endpoints

Crawl a website

Follow links across a site and scrape every page you allow, as one job you can watch, pause and page through.

  • The eyebrow is the nav group, not a breadcrumb trail. Titles are sentence case; leads are one or two sentences that say what the page lets you do.
  • Under 640px the copy button moves under the lead.

Prose

Put rendered Markdown inside .fd-prose and plain elements are styled without classes: 16/28 body, 24/32 and 20/28 headings, ink links with a quiet underline, 12px inline code on a 6% wash. Hover a heading for its link.

Crawl starts at one URL and follows the links it is allowed to, scraping each page into the formats you ask for. A crawl of 500 pages usually finishes in under two minutes; see rate limits for what your plan allows, or read the crawl announcement.

Limit the crawl

Set limit to cap the number of pages and maxDepth to stop following links after a number of hops. Press ⌘ K and type /crawl to jump to the reference.

Include and exclude paths

Paths are regular expressions matched against the URL path, not the full URL.

  • includePaths keeps only matching pages.
    • An empty list keeps everything.
    • Patterns are case-sensitive.
  • excludePaths drops matching pages, and wins over includes.
  • Query strings are ignored unless ignoreQueryParameters is false.

Ordering

  1. The start URL is scraped first.
  2. Links are queued breadth-first.
  3. Sitemaps are merged in after the first 50 pages.

Before you start a large crawl:

  • Check the site’s robots.txt
  • Run a crawl with limit: 10
  • Add a webhook for crawl.page events

Crawl slowly and identify yourself. Ember sends a clear user agent and honours Crawl-delay by default.

ember crawl https://docs.northwind.dev --limit 500 --max-depth 3

Dense reference text

data-size="sm" sets 14/22 for parameter notes, FAQ answers and changelog entries, where you scan rather than read. Everything else keeps the same rhythm.

  • Headings step down one size.
  • Code and tables stay the same.
  • Only direct children get the reading rhythm, so components placed inside prose keep their own type. Links inside callouts and tables follow the same style.
  • One link style: ink with an underline that darkens. Use .fd-link for the rare accent link, such as an announcement.
  • Tables are wrapped in .fd-doc-table on load so wide ones scroll on their own; the page never scrolls sideways.

Picture frame

The frame for a picture a person supplied: a screenshot of a problem, an upload. It loads only an address that passes safeImageUrl(), holds its space from the first paint, and shows a quiet tile when there is nothing to show. In the app as well as the docs.

  • Pass addresses through safeImageUrl(url, { hosts, data }): https on a listed host, or anything on the page's own origin; never javascript:, blob: or a plain http: address on another host. data-fd-data allows data:image/png and the other raster types.
  • The frame writes data-state (empty, loading, loaded, failed, refused) and fires fd:change with it. Only a loaded picture opens larger. setPicture(frame, url) points it at another address.
  • The loading specimen sets data-state="loading" by hand to hold still; the script sets it while the picture is requested.

Framed code

In docs, .fd-codeblock[data-variant="framed"] sits in a soft 4% frame: tabs on the wash, code on an inner surface. Language tabs stay in sync across the page and across pages.

  • Every code sample is copyable. Use python, node, curl and cli as tab values so groups (and the API request panel) sync.
  • All code-block options still apply: line numbers, highlights, collapse, wrap.

Steps

Use numbered steps for a setup that must happen in order. Each step holds prose and code; the rail ties them together.

  1. Create a signing secret

    In Settings → Webhooks, create a secret and store it as EMBER_WEBHOOK_SECRET.

  2. Verify every request

    Reject any payload whose Ember-Signature header doesn’t match.

  3. Answer within 10 seconds

    Return 204 quickly and do the work in a queue. Slow endpoints are retried with backoff for 24 hours.

Content tabs

Use tabs when the same instructions differ by platform or framework, and the reader needs only one. The indicator is ink.

Add a route handler at app/api/ember/route.ts and read the raw body with request.text() before parsing it.

Mount express.raw({ type: "application/json" }) on the webhook route so the signature is checked against the exact bytes.

Read await request.body() in the endpoint and verify it before calling json.loads.

Callouts, accordions and the assistant tip

Docs reuse fd-callout with five meanings: Note (neutral), Tip (success), Info, Warning and Danger. Use at most one per screen; if everything is a callout, nothing is. FAQs and long optional detail go in an accordion.

Note

Crawl results are kept for 24 hours. Download them or use a webhook.

Tip

Run a crawl with limit: 10 first to check your include paths.

Info

Sitemaps are merged in after the first 50 pages.

Warning

Stealth proxies cost 5 credits per page. Set proxy: "basic" to cap spend.

Danger

Deleting a monitor also deletes its change history. This cannot be undone.

Does Ember respect robots.txt?
Yes, by default. Teams on Enterprise can turn it off for domains they own.
Are failed requests billed?
No. A request that returns a 4xx or 5xx status from Ember costs nothing.

Tip: ask the assistant. It has read every page here and answers with code for your language.

Rules

Do

Keep docs navigation neutral. In a reading context the accent is for the primary button, method badges and the rare announcement link.

Don't

Use accent pills for the current page, or accent underlines for ordinary links. One link style: ink with a quiet underline.

Do

Give every page a lead that says what it lets you do, and end it with a next step: the pager, a card or a link.

Don't

Ship a code sample without a copy button, or a request without its response. Every endpoint shows both.

Do

Use the same tab values (python, node, curl, cli) everywhere so a reader’s language follows them.

Don't

Stack callouts or put a table inside a callout. If it matters that much, it belongs in the prose.
