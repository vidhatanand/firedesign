## How Facet should consume it

1. **Opt in with the contract field.** A Facet system that follows Fire stores `{ "contract": "fire/1", "record": <theme record> }` (as `theme.json`), not the generated tokens. Facet calls `expandTheme(record)` from `fire/js/theme.js` (pure ES module, runs in Node and the browser) for tokens, and `themeToCss(record)` for a stylesheet a strict CSP allows. `content.json` is what Facet shows and validates for the default record (its `contract` field is that record, the same bytes as `theme.json`); for any other record Facet regenerates it the same way (palette, type set and dials change, the scales do not).
2. **Pin the release.** Fire 0.6.2, git tag `v0.6.2` (`github:vidhatanand/firedesign#v0.6.2`). The extras bundle hash is `168a3c7993c8ae9871bb6d5ed28efeea1b55ef0d538bfdd3391efb7b3c0d8c28` (SHA-256 of the lines "sha256  path" of `extras.json` files, in order). A Facet system records the tag and the bundle hash, and verifies each file's hash before an export is offered.
3. **Carry the extras.** Copy every `extras.json` file to the same relative path in the canvas or the export. Fonts marked `required: false` belong to the other type sets (`data-type`); a system on Geist needs only the required ones, and may drop the rest and the matching @font-face rules. Two files have a `ds` field: `contract/catalog.json` and `contract/custom-elements.json` are the ones Facet reads from the canvas as `ds/catalog.json` and `ds/custom-elements.json`.
4. **Use the aliases.** `aliases` maps each custom property Facet generates (`--color-primary`, `--space-4`, `--shadow-md`, ...) to the Fire token with the same value, so a Facet-generated sheet can be written as `--color-primary: var(--fd-accent)` and follow the theme. Fire's tokens stay the source: Facet's `component` references should name Facet tokens only where an alias exists.
5. **Components.** Each component is `<cc-component name="Button" variant="primary">`; its props are the data attributes of the Fire markup (`variant` is `data-variant`, `iconOnly` is `data-icon-only`) and the exporter writes the Fire class (`root` in the catalogue) plus those attributes. A `children` part marks a component that takes content. Facet runs `scripts/lint-markup.mjs` on the export and `scripts/render-equal.mjs` against the board.

## Where Fire's model did not fit Facet's

- **Accent role.** Facet requires an `accent` colour; Fire has one accent. `accent` repeats `primary` and Facet may set another.
- **Surface and status roles.** `raised` (Fire `--fd-surface-raised`), `sunken` (`--fd-bg-sunken`) and the four `on-<tone>` roles (`--fd-<tone>-contrast`, the label on `--fd-<tone>-fill`) are carried, each with its text pairing at 4.5:1 in both themes (`text` on `raised`, `text` on `sunken`, `on-<tone>` on `<tone>`). Fire has no secondary colour, so `secondary` and `on-secondary` are not written.
- **Alpha colours.** Roles must be opaque: `muted` is `--fd-text-3` laid over `--fd-bg` in each mode (the contract does the same). `palette` and `state` keep the alpha as 8-digit hex (accent washes, fills, status backgrounds, lines), rounded to 1/255; state colours that Facet shows as a role (`hover.surface`, `selected.surface`, `disabled.surface`) are laid over `--fd-surface`.
- **Shadows.** Every shadow keeps all its layers (up to 5; `--fd-shadow-accent` has 5) in the light value, and Fire's stronger dark layers go in the shadow's `org.codecrystal.dark` extension. Nothing is folded. Fire's focus ring is a two-layer shadow; Facet's `focusRing` holds its 2px width and 2px offset.
- **Sizes.** All 29 of Fire's pixel sizes are carried, plus `touch` (40px, the default control on a coarse pointer; below the 44px Facet recommends, so its accessibility report shows an advisory). Icon sizes are in `iconSize`. Sizes in `ch` (`--fd-measure`) and unitless ones (`--fd-icon-stroke`) are not dimensions Facet takes.
- **Type scale.** All 16 of Fire's type sizes are steps, with Fire's sizes and line heights in rem and its letter spacing in em, as the CSS writes them. Fire sets no line height for `3xs` and `4xs` (the build uses `--fd-lh-2xs`, as chat.css does for `3xs`) or for `compose` (it uses `--fd-lh-lg`, as agent.css does). Body is `md` (14px, 1.25rem), so Facet's accessibility report shows advisories for body size and line height; Fire sets text 14px on purpose.
- **Numeric figures.** `font.numeric` is `proportional`: Fire sets no figure style on the page. Tabular figures are asked for per use (`.fd-stat`, `.fd-num`, numeric columns, chart labels), and the one type step built for numbers, `stat`, carries `numeric: tabular`. Fire uses tabular figures in 12 component sheets for columns of numbers; those are component rules, not type steps, and are not repeated here.
- **Breakpoints.** Facet's breakpoints are min-width and mobile first; Fire writes `max-width: 640px` for the phone layout and `min-width: 900px` for the wide one. `tablet` is 641px (where the wide layout starts) and `desktop` is 900px. `responsive` overrides are not written: Fire's phone overrides (smaller display and h1, 16px gutter) are max-width rules that a mobile-first override cannot say without inverting the base values.
- **Durations.** `duration` holds the five interaction durations and the stagger. The looping durations (spin 0.7s, shimmer 1.6s, pulse 1.8s, blink 1.1s, dots 1.2s) are left out: they are ambient loops, not transitions, and would make Facet report durations above 500ms. Reduced motion is `remove`: Fire sets `--fd-motion` to 0 and every duration is the token times that.
- **Dials and density.** Corners, density, line weight, text size, contrast, motion and texture are theme-record dials, not tokens Facet can model; they travel in `theme.json`.
- **Component states.** Facet takes any lower-case state name, and a web app must cover empty, loading, error and disabled. Card states map to a short vocabulary (empty, loading, error, success, disabled, hover, focus, pressed, selected, open); names that no pattern takes are dropped (200 of them, mostly transient or per-component states such as closing, dragover, masked or sending; for example accordion:closing, agent:fills the viewport, agent:no session column, app:collapsed rail, app:contained, avatar:away, avatar:offline, avatar:online). States are also read from the CSS selectors that carry the component's class (:hover, :focus, [disabled], [aria-invalid], [aria-busy], [aria-pressed], :checked, [open]); that is a heuristic, not a card.
- **Props.** Fire attributes with values are `enum` props; attributes with no value are `boolean`. `data-state`, `data-fill` and `data-fd-instant` are not props (state is set by the page; the others are layout toggles). Enums with more than 32 values would be strings; none are. `children` is Facet's own name, so no prop is called that; a `children` part says the component takes content. Components that take none are listed in the build script (`VOID`).
- **Examples.** Each `api.example` is a `<cc-component>` tag with the first value of the first two enums, not Fire markup: the docs sections that show the real markup are named in the card (`example`) and in `paths`.
- **Size.** 163 components: 26.6 KiB for the document without them (cap 128 KiB), 303.0 KiB for the components (cap 768 KiB) and 0.3 KiB for the contract (cap 16 KiB), compact bytes; Facet measures canonical bytes, which the installed Facet accepted. Text is cut only where a field overruns its length cap.
