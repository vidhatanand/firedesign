JSON, narrow and read-only

Set by your deploy pipeline.

  • Without script it is a text area with one name = value per line, split on the first =. With script one hidden input of the same name posts the same lines, or a JSON object with data-format="json". Rows with an empty name are left out.
  • Enter in a value adds a row below; Enter in a name moves to its value. Backspace in an empty row removes it. Each input is labelled from the column names (“Scope 2”, “What people see for read:runs”), and the remove button names its row.
  • A name used twice marks both names invalid, says so under the field and stops the form posting. Below about 480px a row stacks: the name and its remove button, the value under them.
  • data-mono="key|value|both" sets identifiers in mono. The text area's id goes to the first name, and disabled, readonly and aria-describedby carry over. Read it with pairsValue(el), replace it with setPairs(el, object), and listen for fd:change.

    Validation

    Built on the browser's constraint validation: write required, type, pattern and minlength as usual, add data-fd-validate to the form, and errors appear on blur and on submit. Once a field has been touched it re-checks as you type, so errors clear the moment they are fixed.

    • Messages come from the browser's validity state. Override any of them in the markup with data-error-required, data-error-type, data-error-pattern or data-error-short so they say what to change. For checks only a server can make, call setCustomValidity() and the same error slot shows it.
