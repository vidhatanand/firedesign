Components

Decisions

A person decides what a system or an agent may do: grant credits, allow a host, ship a change. One family covers it: a brief that reads in five seconds, a reason that is the person's own, a button named for its effect, and a few seconds to take it back.

Queue and case

Use it when several decisions wait for one person. Pick one, decide, and the next case opens while the last one counts down.

Nothing waits for you

New requests and agent proposals appear here. Ember emails you when one has a deadline.

  • Write a reason, then commit. The case leaves the queue at once and a held toast counts 10 seconds: nothing is sent until it ends. Undo, or Ctrl Z, puts the case back with your reason in it.
  • Below 800px of width the queue shows the list or the case, never both; the case has a Queue button back. Arrow keys, Home and End move along the list.
  • Every commit names its effect. Decline is a commit too: it needs the reason, and it is held the same way.

Which part when

Start from the brief and the commit. Add the rest only when the decision needs it.

PartUse it whenLeave it out when
fd-decisionSomeone must decide, and getting it wrong costs money, access or trust.The action is routine and undoable: a plain button and a toast do.
fd-draftAn agent wrote the reason or the recommendation for the person.Nobody drafted anything. Never fill the reason field with an agent’s words.
fd-commitThe decision needs a reason that someone reads later: an audit, the requester, the agent.A yes or no with no record, such as dismissing a tip.
fd-impactThe change reaches more than the one thing on screen: “29 teams change”.It touches one record, which the brief already names.
fd-previewThe person edits a value first, and the reach depends on what they type.Nothing is edited: show the fd-impact in the case.
fd-holdSending is hard to take back: money, access, a message, a shipped change.The server can undo it later: use Done · Undo instead.
toast.holdThe page moves on after the commit: a queue, a list, a batch.The person stays on the case: the inline fd-hold reads better.
toast({ undo })It is done, and the server can reverse it for a few seconds.Nothing should happen until the person is sure: hold it.
fd-decision-outcomeThe case stays on screen after the decision, or can be reopened from a link.The case leaves view at once (a queue): the toast says it.
fd-statesAlways, around the screen or the section: loading, empty, error, no access, not found, switched off, expired.Never; a screen without its states is not finished.

WindowWhat has happenedUse
Seconds beforeNothing. It goes when the countdown ends.fd-hold on the case, or toast.hold when the page moves on. 10 seconds; 5 inside a dialog.
Seconds afterIt is done, and the server can reverse it.toast({ title, undo }): Done · Undo for 8 seconds.
Days afterIt is done and recorded; reversing it is a new action.fd-decision-outcome with Undo and the date it stops working.
  • The ring drains with the time left and the number counts whole seconds. Focus moves to Undo when the hold starts; Undo or Esc stops it, and focus returns to the button that started it.
  • Screen readers hear “Approving the credit in 10 seconds. Undo or Escape stops it.” when it starts, and “Stopped. Nothing was sent.” when it is undone. The count itself is silent.
  • A held toast has no close button and cannot be swiped away: closing it would have to mean send or stop. Ctrl Z (⌘ Z) outside a text field presses the newest Undo.
  • Leaving the page while a hold runs sends it at once, with detail.cause “pagehide”: send it with fetch(…, { keepalive: true }).
  • Events: fd:hold when it starts, fd:undo when it is stopped, fd:commit when it goes. Send the request on fd:commit, never earlier.
